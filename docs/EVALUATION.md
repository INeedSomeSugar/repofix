# 任务与评测协议

本项目内置五个自行编写的合成开发任务：CSV 解析、滑动平均、跨文件区间合并、TTL 缓存和词频排序。完整规范在每个任务的 issue 和 README 中，评分断言覆盖规范中的额外输入。

任务源数据由 `scripts/build_fixtures.py` 生成，保存为 `src/repofix/fixtures/cases.json`。数据包含原始源码、可见测试、独立测试和仅用于固定回放的参考修改。真实模型请求只得到任务规范、可见仓库和公开测试结果，不得到参考实现或独立评分断言。

“独立测试”表示断言不进入模型可见目录；这些样例不是外部人工审核基准，也不是 SWE-bench。所有当前任务属于开发集，尚未建立冻结的外部测试集。

## 评分规则

一次修复计为 `verified`，必须满足：

1. 初始公开测试确实失败，且测试发现数量大于零。
2. 原始测试和说明文件的哈希保持不变。
3. 源码确实改变。
4. 最终公开测试全部通过，没有跳过测试。
5. 独立评分测试全部通过，没有跳过测试。

模型自述“修复完成”、HTTP 200 或只通过公开测试，都不足以获得通过状态。保存任务哈希和补丁哈希，用来绑定评分对象。

## 两种策略

`feedback`：模型可根据公开测试结果继续迭代，直到结束或达到预算。

`single_patch`：模型可以先读代码和原始失败记录；首次修改源码的一批工具调用执行后，程序直接评分，不把修改后的测试反馈提供给模型继续修复。它是具有工具读取能力的单次补丁基线，不是纯文本一次回答。

两种策略使用相同模型、任务和配置上限。实际轮数、token 和时间不同，必须同时报告；不能将效果差异全部归因于反馈而忽略更多计算量。`max_observed_tokens` 是根据接口返回用量检查的停止阈值，当前调用可能越过阈值，不是严格的预付费或计费上限。

`replay`：按预先写好的脚本执行已知修改。它用于检查工具、恢复、评分和页面，不计算真实模型修复率。缺失 token 不估算。

## 本次真实模型运行

以下为v0.1历史试验。v0.2已完成五任务、两策略、每任务重复两次的20次真实模型试验，single_patch为10/10、feedback为9/10；完整协议、成本和失败分析见 [v0.2记录](EVALUATION_V02.md)。本轮仍为本地可信合成开发任务，未运行外部保留基准。

实际记录见 [原始 JSON](../reports/deepseek-development-v01.json) 和 [脚本派生摘要](../reports/deepseek-development-v01.md)。

DeepSeek 模型目录实际返回 `deepseek-flash`，该模型完成 CSV 和跨文件区间合并两个任务的两种策略，共四次真实运行；四次均通过对应的公开与独立测试。

| 策略 | 当前样例通过 | 实际累计 token | 累计耗时 |
| --- | --- | ---: | ---: |
| feedback | 2 / 2 | 32,830 | 26.437 秒 |
| single_patch | 2 / 2 | 11,676 | 13.563 秒 |

这两个简单开发任务上没有观察到修复率差异，反馈策略消耗更多 token 和时间。数据不足以得出反馈策略提升修复率的结论；也不能把开发样例的全通过写成通用修复准确率。

## 复现

```powershell
cd D:\User\AI\repofix
.\.venv\Scripts\python.exe -m repofix.cli evaluate --provider replay --out reports/replay-new.json
.\.venv\Scripts\python.exe -m repofix.cli evaluate --provider deepseek --cases csv_records merge_intervals --strategies feedback single_patch --out reports/deepseek-new.json
```

真实模型调用需要已授权的 DeepSeek 凭据，并产生实际 API 用量。报告默认不覆盖。所有尝试都进入分母，包括上游错误和达到预算的运行；按供应商、精确模型名与策略分别统计。
